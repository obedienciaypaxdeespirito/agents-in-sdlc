Copilot を Agent モードで使うと、コードベースを調査し、変更を提案してファイルを編集し、コマンドを実行するなど、自律的に作業します。VS Code の Copilot Chat では、ユーザーのマシンでリアルタイムに実行されるツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を採用または取り消し、エディターを離れずに追加のプロンプトを送って作業を調整、拡張できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視する。
- 提案されたファイル編集をレビューして採用する。
- 実行中のセッションにライト モードの切り替えを追加するよう依頼する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントが、ハイコントラスト モードを実装しています。作業中、デザイン チームから、既定のテーマが暗すぎると感じるユーザー向けにライト モードも追加してほしいという依頼がありました。新しい会話を最初から始めず、既存のセッションに追加の作業を依頼します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調査したファイル、実行したコマンド、提案した編集など、各ステップが表示されます。ファイル編集は差分と **Keep** / **Undo** の操作を含めてチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中、チャットをスクロールして各ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナル コマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を取り消し、エージェントに再試行させます。
4. チャット上部の **Files changed** 表示を開くと、このセッション中にエージェントが変更したすべてのファイルを確認できます。

> [!NOTE]
> ツール呼び出し（例: ターミナル コマンドの実行）が許可を求めた場合、エージェントは一時停止して **Allow** を表示します。実行してもよいコマンドだけを許可してください。

5. エージェントがハイコントラスト モードの実装を終えるまで待ちます。最後に、変更内容をまとめたメッセージが表示されます。

## エージェントにライト モードを追加するよう依頼する

ハイコントラスト モードができたので、同じ会話でライト モードの切り替えを追加します。同じチャット セッションを続けるため、エージェントは前の作業、変更したコンポーネント、スタイル設定の方法、ローカル ストレージのパターンを把握しています。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは前の変更を確認し、ライト モードの追加に取り組みます。
3. ハイコントラスト モードの場合と同様に、新しい編集を確認します。差分ごとに **Keep** または **Undo** を選びます。
4. 望まない方向に進み始めた場合（たとえば切り替え UI を意図しない形にリファクタリングする場合）は、チャット入力欄の隣にある **Stop** ボタンで停止し、明確な追加メッセージを送信します。

> [!TIP]
> 進行中のセッションを案内すると、最初からやり直すよりも時間を短縮できます。追加プロンプトで調整（「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」）、修正（「3 つ目の切り替えを追加せず、ライト モードを既存の設定パネルに統合する」）、作業範囲の拡張（「両方の切り替えにキーボード ショートカットも追加する」）を依頼できます。

## 作業対象をレビューする

コミットする前に、エージェントが変更したすべてのファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントが使うアクセシビリティ パターン（ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持）が反映されていることを確認します。
4. 問題がなければ **Source Control** パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の Agent モードを使って、進行中のセッションを監視し、案内しました。ファイル編集を確認し、変更を採用または取り消し、コンテキストを保ったまま追加プロンプトで作業を拡張しました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を採用または取り消す。
- 実行中のセッションに追加プロンプトを送って作業を案内する。

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボを通じてローカルのカスタム エージェントが作成した変更をレビューします。
